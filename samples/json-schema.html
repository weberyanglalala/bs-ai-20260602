從商品畫面反推 JSON Schema

這是一份靜態 Tailwind CDN 範例頁。四個 Step 使用相同的商品卡視覺風格， 但逐步增加畫面欄位，讓學生理解為什麼 schema 需要 string、number、integer、boolean、object、array、enum、null、anyOf。

Teaching Flow

Step 1 基礎 Step 2 型別 Step 3 巢狀 Step 4 完整

課堂使用方式

每個 Step 都先看畫面，再問學生：「這張商品卡需要哪些欄位？」接著把畫面元素對應回 JSON Schema。 同一套視覺樣式能讓學生專注在資料結構如何變複雜，而不是被不同設計干擾。

string：商品名稱、文案 number：價格、重量 integer：庫存、排序 boolean：是否免運 object：價格、規格 array：多個標籤 enum：分類、狀態 null：尚無日期 anyOf：多種內容區塊

Schema Design Prompt

當 UI 有「多區塊、多標籤、多狀態」時，就應該把資料拆成可維護的 object； 當畫面要限制固定選項，就加入 enum；當某些欄位可能還沒有值，使用 null；當內容區塊有多種結構，使用 anyOf。 

{
  "schema_version": "v1",
  "product": { "product_name": "ThermoMate 500ml 智慧溫控保溫杯" },
  "specifications": {
    "capacity_ml": 500,
    "weight_g": 310.5,
    "colors": ["霧黑", "奶茶白", "海鹽藍"]
  },
  "marketing": {
    "promotion_tags": [
      { "label": "限時 82 折", "tag_type": "discount", "badge_style": "danger" },
      { "label": "滿千免運", "tag_type": "free_shipping", "badge_style": "success" }
    ]
  },
  "content_block": {
    "block_type": "bullet_list",
    "title": "為什麼適合每天使用",
    "bullets": ["容量剛好", "瓶身輕巧", "標籤可展示"]
  }
}

Classroom Wrap-up

從 UI 回到 Schema 的提問句

畫面只顯示一個值？

通常是 string、number、integer 或 boolean。

畫面顯示多個重複項目？

通常是 array，items 可以是 string 或 object。

畫面有固定狀態或分類？

適合用 enum 限制模型輸出。

畫面區塊可能有多種版型？

可以用 anyOf 設計可變內容結構。
